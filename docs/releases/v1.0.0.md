# v1.0.0 — ZTE ZXHN H199A

OpenWrt **24.10-SNAPSHOT**, Linux **6.6.151**, target `armsr/armv7`, for the
ZTE/Sanechips ZX279128S Ethernet router. This re-release includes the bank-aware
installer and reviewed documentation in a single initial source commit.

This is a **single-unit port**. Read the
[validation record](https://github.com/ADCDS/openwrt-zte-h199a/blob/v1.0.0/VALIDATION.md)
and [installation guide](https://github.com/ADCDS/openwrt-zte-h199a/blob/v1.0.0/docs/INSTALL.md)
before flashing.

## Installation and upgrades

The stock web updater writes the inactive firmware bank. One bank-aware image
supports stock A → OpenWrt B and stock B → OpenWrt A. The Python client and
browser-upload format are documented in
[stock web installation](https://github.com/ADCDS/openwrt-zte-h199a/blob/v1.0.0/docs/INSTALL-NO-UART.md).
Native `sysupgrade` updates the running bank, regenerates its unit-specific
header in RAM, and verifies rootfs, kernel and header writes in that order.
The peer firmware stays read-only under OpenWrt.

**The downloads are a bench-unit reference build.** Before installing on
another unit, obtain its own recoverable full NAND backup, exact 128 KiB header
and stock MT7603 calibration, then build with those inputs. The release header
and calibration are not a universal factory image. Confirm the reserved
**84–100 MiB UBI window is safe to initialize**: the first-boot marker guard
does not detect arbitrary non-UBI data and can format that area.

The web upload itself sends no UART commands; backup/input acquisition and
recovery are separate prerequisites. UART/TFTP recovery remains available,
with a bank-A-only guarded helper and explicit physical-target checks.

## Verified behavior and limits

- Wired SSH/LuCI, WAN DHCP and routing/NAT; three LAN interfaces and one WAN
  are configured. Latest-image checks cover LAN1/WAN; other jacks have earlier
  production evidence and remain due for a fresh integrated regression.
- Calibrated 2.4 GHz AP and persistent UBIFS configuration.
- Both-bank web installation and changed-payload native upgrades, with exact
  active-bank MTD/SPI policies and peer/calibration/configuration preservation.
- Earlier watchdog, indicator/button GPIO and manual datapath-recovery results;
  their image-specific limits remain in the validation record.

Earlier short wired NAT measurements were **360.2/307.1 Mbit/s** without
software flow offload and **378.7/375.7 Mbit/s** with it enabled. The recipe does
not force the lab's enabled firewall setting onto a fresh installation.
These are not new hours-long or full-duplex measurements of this asset set.

**5 GHz remains unreliable and is not repaired.** It passed short local
278.7/289.7 Mbit/s transfers before PCIe configuration/accessibility failure.
Later stock and OpenWrt boots also failed port-0 link initialization. The cause
remains unresolved; permanent board damage is not established. Keep it disabled
for normal use. Hardware per-flow offload is also disabled and unqualified;
negative GE-to-GE experiments do not prove it can never be implemented.

Stock `syn_version` can clone its running image into the peer after a default
**300 seconds**, replacing OpenWrt on fallback. Avoid synchronization/upload
races. Fresh bank-aware power-cut qualification, latest-image LAN2/LAN3 and
integrated WPS/reset/LED tests, automatic full datapath-stall recovery and
long-duration mixed-load testing remain outstanding.

The recreated production assets passed fresh stock A → OpenWrt B and stock B →
OpenWrt A installs with the same web container, in **98.56 / 98.92 seconds**.
Both used automatic source-bank detection and zero UART bytes during upload.
Native A changed image 04 → v1.0.0; native B reinstalled the exact released
v1.0.0 archive with the same payload. Earlier changed-payload upgrades on both
banks are recorded separately in validation. Flash readback, write-protection,
stock-peer and all 13 original configuration/SSH-key hashes passed. The final
v1.0.0 A boot also passed an onboard 2.4 GHz association, ten zero-loss pings
and LuCI access. Host CI ran **677 tests, 151 skipped**; the diagnostic actual-C
checker passed 13 cases. These results do not extend the earlier throughput
measurements or qualify 5 GHz reliability.

## Downloads

Use `SHA256SUMS` to check the complete matched set before selecting an image:

| File | Purpose |
|---|---|
| `openwrt-armsr-armv7-zte_h199a-webflash.bin` | Vendor-format stock web upload; not the native tar |
| `openwrt-armsr-armv7-zte_h199a-squashfs-sysupgrade.tar` | Native OpenWrt upgrade archive |
| `kernel`, `rootfs`, `header` | Matching reference parts; direct UART/TFTP procedure targets A only |
| `BUILDINFO.json` | Profile, payload provenance, sizes and hashes |
| `SHA256SUMS` | Checksums for the downloadable files above |

The ordinary production build disables Ethernet/packet-processor debug and
experimental offload controls. Optional diagnostic patches under
`tools/diagnostics` are not applied by `build.sh` and are not included in this
firmware. Source archives are generated from the recreated `v1.0.0` tag.
